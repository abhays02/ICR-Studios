01 / problem

End-to-end ICR doesn't fail
at recognition.
It fails before it reads.

Take a state-of-the-art line recognizer and give it a perfect crop of a handwritten line: character error rate lands near 0.10. Run the same weights, untouched, behind the reference line detector on a full page — the crops it produces are missing, clipped or empty — and end-to-end CER blows out to 0.56.

On handwriting the gap is worse than a number: detector line recall approaches zero. Faint ballpoint and pencil strokes never cross the print-tuned threshold, so lines are never boxed, never cropped, never read. The recognizer is never even asked.

NAYEN v1 does not retrain the recognizer. Indra attacks the stage where the loss actually happens — detection thresholds, box growth, crop geometry, adaptive re-detection — and Laya gates whatever survives. The profile system exists so the delta is measured against the same weights, not asserted.

Third-party measurements published by the model authors (datalab-to/indra-ocr (opens in a new tab)), not by us, and not on banking data. We cite them because they locate the bottleneck; we will publish our own nayen-cli eval numbers when the engine ships. Until then: no accuracy claims on this site.

04 / adapters

One engine.
Swappable backends.

The Rust core never touches a runtime. It speaks one seam — Executor / ModelAdapter — and emits a single InferRequest at a time, waiting to be handed outputs back. The same engine binary logic therefore runs:

  • native · ort nayen-cli loops synchronously over ONNX Runtime C bindings. Desktop + evaluation harness.
  • browser · onnxruntime-web this page. The WASM driver awaits session.run() between engine steps — single-threaded wasm backend, no cross-origin isolation needed.
  • future · GGUF / candle the seam is a trait: a new adapter is a new way to answer InferRequest, nothing else changes. Not implemented — listed as direction, not as a feature.

Why WASM never blocks

Rust compiled to WASM cannot block on a JS promise — so it never tries. The engine is a request/response state machine; the host owns all async.

engine nayen_start → HostStep
InferRequest
host driver web/src/engine/wasm-driver.ts
session.run()
ort-web wasm backend · 1 thread
outputs → scratch → nayen_feed
done → PageResult (lines · markdown · fields · timings)

Tensor payloads never travel through JSON: TensorRef is an offset + length into the WASM linear-memory scratch buffer. Only shapes and control flow cross as text.
